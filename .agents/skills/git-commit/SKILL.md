# Git Commit Skill

## 1. Purpose

Gitの変更内容を確認し、適切なコミットメッセージを作成して、
Git commitを実行してください。

コミットメッセージは必ず英語で作成してください。

ユーザーが手動でGitコマンドを実行する必要がないように、
可能な限りエージェント自身でGit操作を完結させてください。

## 2. Execution Rules

### 2.1. Basic Rules

- Gitコマンドはターミナルから実行してください。
- Gitの状態や差分は、実際のGitコマンドの実行結果を根拠に判断してください。
- 変更内容を確認せずにコミットしてはいけません。
- 既存のユーザー変更を破棄してはいけません。
- ユーザーが作業中の変更を勝手にステージング対象から除外・変更してはいけません。
- コミットメッセージは英語で作成してください。
- Git操作に失敗した場合は、エラー内容を表示して処理を停止してください。

### 2.2. Git Operation Failure

Git操作に失敗した場合、以下を実行してください。

1. 失敗したコマンドを表示する。
2. エラーメッセージを表示する。
3. 原因が分かる場合は、その原因を簡潔に説明する。
4. ユーザーに必要な操作を具体的に依頼する。
5. それ以上のGit操作を行わずに終了する。

禁止事項:

- エラーを無視して処理を続行すること。
- ユーザーの許可なく強制的な復旧操作を行うこと。
- `git reset --hard` を実行すること。
- `git checkout --` や `git restore` によって変更を破棄すること。
- `git push --force` を実行すること。
- コミット失敗時に原因を確認せず、別の方法で強引にコミットすること。

## 3. Workflow

以下の順番で実行してください。

### Step 1: Git Repository Check

Gitリポジトリ内であることを確認してください。

```bash
git rev-parse --is-inside-work-tree
```

失敗した場合は処理を停止してください。

### Step 2: Check Git Status

現在のGitの状態を確認してください。

```bash
git status --short
```

変更が存在しない場合は、コミットする変更がないことをユーザーに伝えて終了してください。

### Step 3: Analyze Changes

以下のコマンドを実行して変更内容を確認してください。

```bash
git diff --stat
git diff
git diff --cached --stat
git diff --cached
git status --short
```

未追跡ファイルがある場合は、必要に応じてファイルの内容も確認してください。

確認する項目:

- 変更されたファイル
- 追加されたファイル
- 削除されたファイル
- 修正された機能や処理
- バグ修正の有無
- ドキュメントや設定ファイルの変更
- 変更同士の関連性

差分が大きい場合は、必要に応じてファイル単位で確認してください。

変更内容を十分に理解できない場合は、推測でコミットメッセージを作成せず、ユーザーに確認してください。

### Step 4: Generate Commit Message

変更内容を分析し、適切なGit commitメッセージを作成してください。

コミットメッセージは必ず英語にしてください。

#### Message Format

```text
<type>(<scope>): <summary>

- <detail 1>
- <detail 2>
- <detail 3>
```

#### First Line

形式:

`<type>(<scope>): <concise summary>`

typeは変更内容に応じて選択してください。

| Type | Description |
|---|---|
| feat | 新機能の追加 |
| fix | バグ修正 |
| docs | ドキュメントの変更 |
| refactor | リファクタリング |
| test | テストの追加・修正 |
| chore | 設定・依存関係・雑務 |
| perf | パフォーマンス改善 |
| style | フォーマットやスタイルの変更 |
| build | ビルド関連の変更 |
| ci | CI/CD関連の変更 |
| revert | 変更の取り消し |

scopeは変更対象の機能、モジュール、ディレクトリなどを簡潔に表してください。

scopeが適切でない場合は省略しても構いません。

#### Second Line

必ず空行にしてください。

#### Third Line and Beyond

変更内容を英語の箇条書きで具体的に記述してください。

- 変更した内容を簡潔に記述する。
- 変更の目的や理由が分かる場合は含める。
- 実際の変更内容に基づいて記述する。
- 推測や実装されていない内容を記述しない。
- 不必要に長い説明は避ける。

### Step 5: Display Commit Message

作成したコミットメッセージをターミナルに表示してください。

この時点では、まだコミットを実行しないでください。

### Step 6: Stage Changes

コミット対象を確認し、ステージングしてください。

原則として、今回の変更を適切にコミットするために必要なファイルだけをステージングしてください。

既にステージングされている変更がある場合は、その内容も確認し、ユーザーの変更を勝手に解除・上書きしないでください。

ステージング後、以下を実行してください。

```bash
git diff --cached --stat
git diff --cached
```

ステージングされた内容が、作成したコミットメッセージと一致していることを確認してください。

### Step 7: Execute Git Commit

作成したコミットメッセージを使用してコミットしてください。

複数行のメッセージは、シェルの安全な引数渡しを利用して指定してください。

例:

```bash
git commit -m "feat(logger): add structured logging support" \
  -m "- Add structured log records" \
  -m "- Support configurable log levels"
```

実際のコミット内容に合わせてメッセージを指定してください。

コミットに失敗した場合は、Section 2.2に従ってください。

### Step 8: Verify Commit

コミットが成功したら、以下を実行してください。

```bash
git status --short
git log -1 --format="%h %s"
```

コミットが作成されたことを確認してください。

未コミットの変更が残っている場合は、その旨をユーザーに伝えてください。

## 4. Completion Report

正常に完了した場合、以下の情報をユーザーに報告してください。

- コミットハッシュ
- コミットメッセージ
- コミットしたファイルの概要
- 未コミットの変更が残っている場合は、その内容

## 5. Important Notes

- コミットメッセージは必ず英語にしてください。
- Git操作は実際のコマンドを実行してください。
- コマンドの実行結果を確認してから次のステップへ進んでください。
- コミット対象とコミットメッセージの内容を一致させてください。
- エラー発生時は処理を停止し、ユーザーに操作を依頼してください。
- ユーザーの既存変更を破壊しないことを最優先にしてください。
