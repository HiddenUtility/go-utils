## 5. Technical Decisions

### Decision 1: Generics for JSON functions

- **Background:** The requirement was to support arbitrary Go structures.
- **Options:** Using `interface{}` (pre-Go 1.18) or Generics.
- **Selected:** Generics (`[T any]`).
- **Reason:** Provides type safety at the call site and avoids unnecessary type assertions/casting in user code.
- **Impact:** Improved developer experience and compile-time safety.

### Decision 2: DTO/Domain Separation

- **Background:** The spec explicitly requested separation to handle validation and defaults.
- **Options:** Using a single model for both JSON and business logic.
- **Selected:** Separate `models.UserDTO` and `models.User`.
- **Reason:** DTOs are optimized for wire format (using pointers for nullability), while Domain models are optimized for business logic (using values for stability).
- **Impact:** Clean separation of concerns and easier validation.
