# Go Text Logger 実装仕様書の作成・実装指示

## 1. 目的

Go言語で、ファイル出力に対応したシンプルなログライブラリを実装してください。

このライブラリは、ログレコードを一時的にメモリへ蓄積し、指定されたタイミングでファイルへ書き出します。

以下の機能を実装してください。

- ログレベルの管理
- ログレベルによる出力フィルタリング
- ログレコードの生成
- ログレコードの一時蓄積
- 複数レコードの一括追加
- ファイルへのログ出力
- ファイルサイズに応じたローテーション
- リアルタイム出力の切り替え
- 明示的な終了処理

実装はGoの標準ライブラリのみを使用してください。外部ライブラリは追加しないでください。

---

## 2. 実装上の基本ルール

以下のルールを必ず守ってください。

1. Goの標準的なコーディング規約に従うこと。
2. 公開する型・関数・メソッドには適切なGo形式のコメントを付けること。
3. ファイル操作で発生したエラーを握りつぶさないこと。
4. エラーは原則として戻り値で呼び出し元に返すこと。
5. ログレコードの追加時に、設定されたログレベルによるフィルタリングを行うこと。
6. 内部バッファに蓄積したログレコードは、正常にファイルへ書き出せた場合にのみ削除すること。
7. ファイルのローテーション処理で既存ログを意図せず消失させないこと。
8. テストを実装し、正常系と異常系の両方を確認すること。

## 3. ログレベル

### 3.1 LogLevel型

ログレベルを表す独自の整数型 `LogLevel` を定義してください。

以下の定数を定義してください。

- `CRITICAL`
- `ERROR`
- `WARNING`
- `INFO`
- `DEBUG`

ログレベルには、次の優先順位を設定してください。

| ログレベル | 優先順位 |
|---|---:|
| CRITICAL | 5 |
| ERROR | 4 |
| WARNING | 3 |
| INFO | 2 |
| DEBUG | 1 |

優先順位を比較できるようにしてください。

ログレベルの大小比較は、定数の数値に依存することを明確にし、必要に応じて比較用のメソッドまたは関数を実装してください。

### 3.2 ログレベルのフィルタリング

Loggerは、出力対象とする最低ログレベルを保持します。

設定されたログレベル以上の優先順位を持つログだけを受け付けてください。

例：

| Loggerの設定 | 受け付けるログ |
|---|---|
| CRITICAL | CRITICAL |
| ERROR | CRITICAL、ERROR |
| WARNING | CRITICAL、ERROR、WARNING |
| INFO | CRITICAL、ERROR、WARNING、INFO |
| DEBUG | すべて |

たとえば、LoggerのログレベルがINFOの場合、DEBUGのログは内部バッファに追加しないでください。

## 4. LogRecode構造体

### 4.1 構造体の定義

ログレコードを表す `LogRecode` 構造体を定義してください。

以下のフィールドを持たせてください。

| フィールド | 型 | 説明 |
|---|---|---|
| Timestamp | string | ログ生成日時 |
| Level | LogLevel | ログレベル |
| Msg | string | ログメッセージ |
| Pid | int | プロセスID |

### 4.2 ログレコードの生成

ログレコードを生成するための関数を用意してください。

以下の関数を実装してください。

- `NewCritical(msg string) LogRecode`
- `NewError(msg string) LogRecode`
- `NewWarning(msg string) LogRecode`
- `NewInfo(msg string) LogRecode`
- `NewDebug(msg string) LogRecode`

各関数は、指定されたログレベルのLogRecodeを生成して返してください。

生成時には、以下の値を自動設定してください。

**Timestamp**

- ローカル時刻を使用すること。
- タイムゾーン情報は含めないこと。
- マイクロ秒まで記録すること。
- 形式は `YYYY-MM-DDTHH:MM:SS.ffffff` とすること。

Goの`time.Time.Format`を使用し、以下のレイアウトを使用してください。

`2006-01-02T15:04:05.000000`

**Pid**

- `os.Getpid()`で取得すること。

### 4.3 ToLogメソッド

`LogRecode`に`ToLog() string`メソッドを実装してください。

ログレコードを、次の形式の文字列に変換して返してください。

`Timestamp [LEVEL] [PID] Msg`

例：

`2026-11-14T12:34:56.123456 [INFO] [1234] application started`

ログレベルは大文字で出力してください。

## 5. Logger構造体

### 5.1 構造体の定義

ログ出力を管理する`Logger`構造体を定義してください。

以下のフィールドを持たせてください。

| フィールド | 型 | 説明 |
|---|---|---|
| Path | string | ログファイルのパス |
| Recodes | []LogRecode | 出力待ちのログレコード |
| MaxFileNum | uint32 | ログファイルの最大数 |
| MaxFileSize | uint32 | ログファイルの最大サイズ（バイト） |
| Realtime | bool | リアルタイム出力の有効・無効 |
| LogLevel | LogLevel | 出力対象とする最低ログレベル |
| NowSize | uint32 | 現在のログファイルサイズ（バイト） |

フィールドへのアクセス範囲は、ライブラリの利用方法に合わせて設計してください。

外部から直接変更させる必要がないフィールドは非公開にして構いません。ただし、実装時には本指示書で定める機能と振る舞いを維持してください。

### 5.2 デフォルト設定

以下のデフォルト値を使用してください。

| 設定 | デフォルト値 |
|---|---|
| MaxFileNum | 7 |
| MaxFileSize | 200 * 1024 |
| Realtime | false |
| LogLevel | INFO |

MaxFileSizeの単位はバイトです。

200 * 1024は200 KiBを意味します。

### 5.3 New関数

次の関数を実装してください。

`New(path string) (*Logger, error)`

ログファイルのパスだけを指定してLoggerを生成します。

その他の設定には、すべてデフォルト値を使用してください。

### 5.4 NewWith関数

次の関数を実装してください。

`NewWith(path string, maxFileNum uint32, maxFileSize uint32, realtime bool, logLevel LogLevel) (*Logger, error)`

各引数の意味は以下のとおりです。

| 引数 | 説明 |
|---|---|
| path | ログファイルのパス |
| maxFileNum | ログファイルの最大数 |
| maxFileSize | ログファイルの最大サイズ（バイト） |
| realtime | リアルタイム出力の有効・無効 |
| logLevel | 出力対象とする最低ログレベル |

NewとNewWithは、初期化処理を共通化してください。

初期化時には、以下を行ってください。

1. 引数を検証する。
2. Loggerの各フィールドを初期化する。
3. ログファイルが既に存在する場合は、現在のファイルサイズを取得する。
4. ログファイルが存在しない場合は、現在のファイルサイズを0とする。
5. ログ出力に必要なディレクトリが存在しない場合は、必要に応じて作成する。

不正な引数やファイル操作エラーが発生した場合は、エラーを返してください。

`maxFileNum`は1以上でなければなりません。`maxFileSize`も1以上でなければなりません。

## 6. Loggerのログ出力メソッド

Loggerに、以下のメソッドを実装してください。

- `Critical(msg string) error`
- `Error(msg string) error`
- `Warning(msg string) error`
- `Info(msg string) error`
- `Debug(msg string) error`

各メソッドは、対応するログレベルのLogRecodeを生成し、内部バッファへ追加してください。

### 6.1 ログレベルのフィルタリング

ログレコードを追加する前に、LoggerのLogLevelとレコードのLevelを比較してください。

レコードの優先順位がLoggerの設定値以上の場合のみ、内部バッファへ追加してください。

設定値より低いログレベルの場合は、何も追加せず、`nil`を返してください。

フィルタリングされたログについては、ファイル出力処理も実行しないでください。

### 6.2 Realtimeの動作

ログレコードの追加後、Realtimeがtrueの場合は`Out()`を実行してください。

Realtimeがfalseの場合は、内部バッファへ蓄積するだけにしてください。

---

## 7. WriteRecsメソッド

複数のログレコードを一括で追加するため、以下のメソッドを実装してください。

`WriteRecs(recs []LogRecode) error`

### 7.1 基本動作

引数で受け取ったログレコードを順番に確認し、LoggerのLogLevelによるフィルタリングを行ってください。

フィルタリングを通過したログレコードだけを、内部のRecodesへ追加してください。

フィルタリングで除外されたログレコードは追加しないでください。

### 7.2 内部バッファへの追加

- 既存のRecodesを削除しないこと。
- 既存のRecodesの後ろに追加すること。
- 引数の順序を維持すること。
- 引数のスライスを変更しないこと。
- 引数のスライスを保持して後から参照するのではなく、レコードの値をLogger側に保持すること。
- LogRecodeのフィールドが今後変更される可能性も考慮し、必要に応じて値をコピーして保持すること。

### 7.3 Realtimeの動作

Realtimeがtrueの場合、対象レコードをすべて追加した後に`Out()`を1回だけ実行してください。

1件ずつ追加するたびに`Out()`を呼び出してはいけません。

Realtimeがfalseの場合は、内部バッファへ蓄積するだけにしてください。

### 7.4 空配列・全件フィルタリング

以下の場合は、不要なファイル出力処理を実行しないでください。

- 引数のスライスが空の場合。
- フィルタリング後に追加対象のログレコードが1件も残らなかった場合。

いずれの場合も`nil`を返してください。

---

## 8. Outメソッド

内部バッファに蓄積されたログレコードをファイルへ書き出すメソッドを実装してください。

`Out() error`

### 8.1 基本動作

1. 内部バッファが空の場合は何もせず`nil`を返す。
2. 書き出し対象のログレコードを順番に文字列へ変換する。
3. 各ログレコードを改行で区切る。
4. ログファイルへ追記する。
5. 書き出しが正常に完了した場合、内部バッファを空にする。
6. 現在のログファイルサイズを更新する。
7. ローテーションが必要な場合は、ローテーション処理を実行する。

### 8.2 ファイル出力形式

各ログレコードは`ToLog()`で文字列化してください。

1レコードにつき1行で出力してください。

最終レコードの後にも改行を付けてください。

### 8.3 エラー処理

ファイルのオープン、書き込み、クローズなどでエラーが発生した場合は、エラーを呼び出し元へ返してください。

書き込みに失敗した場合は、内部バッファのログレコードを削除しないでください。

次回の`Out()`で再度出力できる状態を維持してください。

ただし、ファイルへの書き込みが成功した後にローテーションでエラーが発生した場合は、既に書き込み済みのログレコードを内部バッファへ戻さないでください。

そうしないと、次回の出力時に同じログが重複する可能性があります。

---

## 9. ログファイルのローテーション

ログファイルのサイズが設定値を超えた場合に、ローテーションを実行してください。

### 9.1 ファイル名

現在のログファイルを`app.log`とした場合、世代ごとのファイル名は次のようにしてください。

- `app.log`：現在のログファイル
- `app.log.1`：1世代前
- `app.log.2`：2世代前
- `app.log.3`：3世代前

実際のファイル名はLoggerのPathを基準にしてください。

### 9.2 ローテーション条件

現在のログファイルサイズがMaxFileSizeを超えた場合にローテーションしてください。

判定条件は次のとおりです。

`NowSize > MaxFileSize`

MaxFileSizeと同じサイズの場合は、ローテーションしないでください。

### 9.3 ローテーション手順

以下の順番で処理してください。

1. 最も古い世代のログファイルを削除する。
2. 既存の世代ファイルを古い番号へ移動する。
3. 現在のログファイルを`.1`へ移動する。
4. 新しいログファイルを作成する。
5. NowSizeを0にする。

例えばMaxFileNumが4の場合、最大で次の4ファイルを保持します。

- `app.log`
- `app.log.1`
- `app.log.2`
- `app.log.3`

MaxFileNumは現在のログファイルを含めたファイル数です。

### 9.4 MaxFileNumが1の場合

MaxFileNumが1の場合、世代ファイルは保持しません。

現在のログファイルを削除し、新しいログファイルを作成してください。

### 9.5 ローテーション時のエラー

ファイルの削除、移動、作成に失敗した場合はエラーを返してください。

ローテーション処理は、既存のログファイルを不必要に消失させないように実装してください。

可能な範囲で、ファイル操作の失敗によってログファイルの状態が不整合にならないようにしてください。

## 10. Closeメソッド

GoにはRustのDropに相当するデストラクタがないため、Loggerの終了時に呼び出す`Close()`メソッドを実装してください。

`Close() error`

### 10.1 基本動作

1. 内部バッファにログレコードが残っている場合は`Out()`を実行する。
2. `Out()`の結果を呼び出し元へ返す。
3. 必要な終了処理を行う。

Loggerが管理するファイルを常時開きっぱなしにする設計にしないでください。ファイルは必要なタイミングで開閉してください。

### 10.2 Closeの複数回呼び出し

Closeが複数回呼び出されても、予期しない動作をしないようにしてください。

2回目以降のCloseで追加のログ出力やファイル操作を不必要に実行しないようにしてください。

## 11. 使用例

以下のようなコードで利用できるようにしてください。

```go
package main

import (
    "log"
    "your-module/logger"
)

func main() {
    lg, err := logger.New("app.log")
    if err != nil {
        log.Fatal(err)
    }

    defer func() {
        if err := lg.Close(); err != nil {
            log.Printf("logger close error: %v", err)
        }
    }()

    _ = lg.Info("application started")
    _ = lg.Debug("debug message")
    _ = lg.Error("something went wrong")

    recs := []logger.LogRecode{
        logger.NewInfo("batch message 1"),
        logger.NewWarning("batch message 2"),
        logger.NewDebug("batch message 3"),
    }

    if err := lg.WriteRecs(recs); err != nil {
        log.Printf("write records error: %v", err)
    }

    if err := lg.Out(); err != nil {
        log.Printf("output error: %v", err)
    }
}
```

※ `your-module/logger`は実際のGoモジュール名に合わせて変更してください。

## 12. テスト

Goの標準テスト機能を使用して、テストを実装してください。

一時ディレクトリは`testing.T.TempDir()`を使用してください。

### 12.1 LogRecodeのテスト

- 各ログレベルのレコードを生成できること。
- Timestampが指定形式で生成されること。
- Pidが現在のプロセスIDと一致すること。
- ToLogが指定形式の文字列を返すこと。

### 12.2 Loggerの初期化テスト

- Newでデフォルト設定が適用されること。
- NewWithで指定した設定が適用されること。
- ログファイルが存在する場合、現在のサイズを取得すること。
- 不正な引数でエラーが返ること。

### 12.3 ログレベルフィルタリングのテスト

各ログレベルを設定した場合に、受け付けるログが正しいことを確認してください。

特に次のケースをテストしてください。

- INFO設定時にDEBUGが追加されないこと。
- INFO設定時にINFO以上が追加されること。
- ERROR設定時にWARNING以下が追加されないこと。
- DEBUG設定時にすべてのログが追加されること。

### 12.4 WriteRecsのテスト

- 複数のレコードを一括追加できること。
- 既存のバッファ内容が維持されること。
- ログレベルに応じてフィルタリングされること。
- 引数のスライスが変更されないこと。
- 空スライスの場合に何も追加されないこと。
- 全件フィルタリングされた場合に何も追加されないこと。
- Realtime=trueの場合、追加後に1回だけ出力されること。
- Realtime=falseの場合、ファイルに出力されずバッファに残ること。

### 12.5 Outのテスト

- バッファのログがファイルへ出力されること。
- 出力順序が維持されること。
- 1レコードにつき1行で出力されること。
- 出力成功後にバッファが空になること。
- 出力失敗時にバッファが維持されること。
- 空バッファの場合に正常終了すること。

### 12.6 ローテーションのテスト

- MaxFileSizeを超えた場合にローテーションされること。
- MaxFileSizeと同じサイズではローテーションされないこと。
- 世代ファイルの番号が正しく更新されること。
- MaxFileNumを超えるファイルが残らないこと。
- MaxFileNum=1の場合に世代ファイルが作成されないこと。
- 古いログファイルが正しく削除されること。

### 12.7 Closeのテスト

- Closeで残りのログが出力されること。
- Closeを複数回呼び出しても問題が発生しないこと。
- Close時の出力エラーが呼び出し元に返ること。

## 13. 品質チェック

実装完了後、以下のコマンドを実行してください。

```bash
gofmt -w .
go vet ./...
go test ./...
```

すべて正常終了することを確認してください。

既存コードを変更する場合は、変更前から存在する問題と今回の変更による問題を区別してください。

テストに失敗した場合は、原因を調査して修正してください。
